# 결정 기록

> 형식: **결정 / 근거 / 주의**. 날짜 필수. 뒤집힌 결정은 지우지 말고 새 항목으로 덮는다.

## D1. 파이프라인 번호가 유일한 축이다 (2026-08-19)

**결정** — 단계 N · 하위 M → 「N-M」 하나로 폴더·스크립트·그림·Notion 절·커밋 메시지를 전부 묶는다.
알파벳 갈래(`4-2a`)는 쓰지 않고, 한 하위 단계가 그림을 여러 장 내면 **번호는 같고 slug만 다르게** 한다.

**근거** — 저장소에 이미 세 개의 서로 다른 번호 축이 섞여 있다: 트랙 번호(`01_Like_slice`…),
논문 재현 번호(`papers/01_Ecker2020`…), 트랙 내부 단계 표기(05의 「N-M」). 축이 늘어날수록
"이 번호가 무엇의 번호인지"를 매번 물어야 한다. 04는 축을 하나로 고정한다.

**주의** — 지원 폴더(`lib/ config/ docs/ mechanisms/ env/ scratch/`)는 번호가 없다.
파이프라인 단계가 아니고, **파이썬이 숫자로 시작하는 모듈을 import 못 하기** 때문이다.
따라서 재사용 코드는 전부 `lib/` 에 두고 번호 스크립트끼리는 import 하지 않는다.

## D2. 한 단계 = 하나의 구성요소, 검증은 그 단계 안에 (2026-08-19)

**결정** — 단계를 7개로 두고 모든 단계를 같은 레벨에 놓는다.
1 환경 · 2 뉴런 · 3 시냅스·전달 · 4 구동·리듬 · 5 가소성 엔진 · 6 실험 · 7 보완 모델.

**근거** — 초안에서 「단기가소성」을 「가소성 엔진」과 나란한 단계로 두었는데 이는 분류 오류였다.
엔진 B·C·GluSynapse가 **단기가소성을 내부에 품고 있으므로** 단기가소성은 엔진의 *능력*이지 동급이 아니다.
같은 오류로 「시냅스 배선」과 「전달 검증」도 나뉘어 있었다 — 구성요소와 그 검증을 쪼갠 것이다.

**주의** — 그 결과 단기가소성 검증은 **5-9(엔진 단계 안의 횡단 검증)** 에 들어간다.
레지스트리의 `caps` 단기가소성 플래그가 5-9의 대상 엔진을 자동 결정하므로,
엔진을 추가해도 검증 코드를 고칠 필요가 없다.

## D3. 1-1 진단 도구는 PowerShell 이다 (2026-08-19)

**결정** — `env/probe_env.ps1`. 스크립트 본문은 **ASCII 전용**.

**근거** — 파이썬이 있는지 확인하는 도구가 파이썬이면 순환이다. 그리고 PowerShell 5.1은
BOM 없는 UTF-8 파일의 한글을 깨뜨리므로, 스크립트 안에 한글을 넣지 않고 한글 보고는
[ENVIRONMENT.md](ENVIRONMENT.md) 에 둔다.

**주의** — 이 때문에 **1-1 만 PNG 산출물이 없다.** matplotlib이 파이썬을 요구하기 때문이다.
산출물은 밑줄 없는 `1-1_env_probe.json`(추적)과 ENVIRONMENT.md 판정표다.
`.gitignore` 의 `_*` 규칙에 걸리지 않도록 **의도적으로 밑줄을 뺐다.**

작성 중 실제로 밟은 함정 2가지 — 둘 다 오류 없이 틀린 값을 내므로 기록한다:
- `OrderedDictionary.Values` 를 파이프에 넣으면 **컬렉션 전체가 단일 객체로 취급**되어
  `(… | Where-Object { $_ }).Count` 가 항상 1이 된다 → Keys 순회로 교체.
- 출력이 없는 스크립트 블록은 `AutomationNull` 을 돌려주고, `ConvertTo-Json` 이 이것을
  `null` 이 아니라 **`{}`** 로 직렬화한다 → 나중에 파이썬에서 `is None` 검사가 깨진다.
  배열 래퍼(`@(& $block)`)로 실제 `$null` 로 접는다.

## D6. 모든 하위 단계는 직관적 산출물을 낸다 (2026-08-19)

**결정** — **N-M 하나하나가 반드시** 눈으로 바로 판단할 수 있는 산출물(그림·그래프·표)을 만들고,
**git 과 Notion 양쪽에 같은 흐름에서** 정리한다. 산출물 없는 하위 단계는 완료로 치지 않는다.

- 그림 파일명 `N-M_<slug>.png` — 여러 장이면 번호는 같고 slug만 다르다.
- 표는 Notion **네이티브 표**로 넣는다(파이프 표 → `<table>` 렌더).
- Notion 절 번호는 파이프라인 N-M 과 **완전히 일치**한다. 페이지 id `3c117cb5cdbd8091af80cba6a08ec5ee`.
- 캡션·표의 **모든 수치는 소스코드/실행 로그와 대조**해 확정한다(기억 의존 금지).
- **하위 단계 하나가 끝날 때마다 사용자에게 보고한다** — 산출 그림을 보내고, 수치·판정·정정사항을
  요약하고, 다음 단계를 예고한 뒤 **확인을 받고 넘어간다.** 여러 단계를 묶어 진행하지 않는다.
- **하위 단계가 끝나면 그 자리에서 즉시 Notion 에도 정리한다** (GitHub 커밋과 같은 흐름).
  나중에 몰아서 하지 않는다. 절 번호는 N-M 과 일치, 그림은 placeholder + 표는 네이티브 표.
- **설명은 쉽게** — 개념은 먼저 일상 비유로, 전문용어는 그 뒤에. 처음 보는 사람이 이해할 수 있게.

**근거** — 수치만 나열된 단계는 나중에 읽는 사람이 옳은지 그른지 판정할 수 없다.
"직관적으로 확인 가능한 산출물"이 각 단계의 통과 증거이자 다음 단계의 근거가 된다.

**주의** — **1-1 은 이 규칙의 유일한 예외였다.** matplotlib 이 파이썬을 요구하는데
그 파이썬이 없다는 것을 확인하는 단계였기 때문이다. 산출물은 `1-1_env_probe.json` + ENVIRONMENT.md 표였다.
→ **1-2 완료 직후 같은 JSON 으로 `1-1_env_probe.png` 를 생성해 소급 보완한다.** (미결 #8)

## D8. 축삭 스텁(replace_axon)을 그대로 쓴다 · pre→post 는 NetCon+지연 (2026-08-20)

**결정** — BBP 템플릿의 `replace_axon()`(실제 축삭 → 60µm 스텁 2개)을 그대로 둔다.
pre→post 전달은 **막 접촉이 아니라 NetCon + 전도지연**으로 만든다. 지연은 우리가 정한 값을
`config/synapse.yaml` 에 노출한다(3-3).

**근거** — 사용자가 "물리적으로 닿아 시냅스를 만들자"고 제안했고, 데이터로 검토한 결과:
1. **닿을 축삭이 없다.** 원본 SWC 축삭은 `replace_axon` 을 꺼도 소마에서 **87µm(pre)/75µm(post)**
   밖에 안 뻗는 잘린 조각이다. 실제 CA1 축삭은 수 mm 를 뻗지만 이 재구성본엔 시작부만 담겼다.
2. **NEURON 에 "닿아서 생기는 시냅스"가 없다.** 시냅스 전달은 항상 POINT_PROCESS(수용체) +
   NetCon(pre 스파이크 → 지연 → 활성화) 이벤트다. BBP 전규모 회로·05 트랙·모든 상세 모델이 동일하다.
   막 접촉으로 자동 방출되는 물리는 어떤 시뮬레이터에도 없다.
3. **축삭은 우리 측정에 영향이 없다.** pre 는 스파이크 시각 공급원일 뿐이고, post 의 EPSP 는
   정단수상돌기 시냅스에서 소마로 내려온다. 축삭(스텁이든 원본이든)은 소마에 매달린 꼬리라
   수상돌기 통합·가소성에 관여하지 않는다.

**주의** — "스텁이 정확도를 떨어뜨리지 않나"는 질문에 대한 답: 축삭 자체만 보면 스텁도 원본도
실제 축삭이 아니다(원본은 잘린 조각). 하지만 **우리가 재는 것**(후시냅스 EPSP·가소성)의 정확도는
축삭이 아니라 수상돌기·이온채널이 좌우하므로 영향이 없다. 오히려 잘린 원본을 살리면 BBP 파라미터가
스텁 기준으로 맞춰져 있어 **발화 특성이 틀어진다.** → 스텁이 파라미터와 일관된 정직한 선택.

**갱신 (2026-08-20, 3-2)** — 사용자 요청("나란히 붙여서 시냅스 형성")에 따라
**두 세포를 3D 인접 배치하고 접촉 지점에 시냅스를 만드는 방식으로 바꿨다.**
- pre·post 수상돌기 필드를 SR 대역에서 겹치게 배치 → post SR 정단 세그먼트가 pre 구조와
  가장 가까운(apposition) 지점에 시냅스.
- **전도지연은 이제 임의값(1.5ms)이 아니라 pre 소마→시냅스 3D 거리 / 전도속도(0.5 m/s) +
  시냅스지연(0.5ms) 으로 계산**한다. 3-2 실측 0.69~0.92 ms.
- 여전히 전달은 NetCon(불가피). 바뀐 것은 시냅스 위치·지연이 **기하에서 나온다**는 점.
- 한계: 이 세포들 축삭이 87µm 조각이라 접촉은 pre 수상돌기↔post 수상돌기 인접으로 잡았고,
  실제 최소 접촉거리는 24~44µm(투영 apposition)라 엄밀한 <2µm 접촉은 아니다. 벤치 도해 수준.

**재갱신 (2026-08-21, 3-2) — 방사축 정렬 + 회전각 탐색으로 배치를 생물학적 근거화**
사용자 제안: 아틀라스 축(방사축)을 기준으로 세포를 회전시켜 인접해지는 각을 쓰자.
- **생물학적 근거**: 모든 CA1 추체세포는 **방사축(SO→SP→SR→SLM)을 따라 정렬**되어 정단이 SLM 쪽을
  향한다. 두 세포의 정단(방사)축을 **평행**으로 두는 것은 임의가 아니라 조직의 실제 방위다.
- **자유 파라미터 = 방사축 둘레 방위각.** CA1 PC 는 방위각에 선호가 없으므로, 이 각을 두 수상돌기
  필드의 **접촉(apposition)이 최대가 되도록** 고른다 = 정당한 모델링 선택.
- **04는 아틀라스를 로드하지 않는다**(독립 트랙). 그래서 세포 고유의 **정단축**을 아틀라스 방사축의
  대응물로 쓴다. `align()` 이 정단을 +y 로 세우므로 +y 가 방사축.
- 절차: 두 세포를 정단축 +y 로 정렬 → 소마를 방사축 수직(측방)으로 거리 L 만큼 벌림 →
  pre 를 정단축(+y) 둘레로 회전각 θ 스윕 → 접촉 최대 θ* 선택 → 그 배치에서 접촉점에 시냅스 →
  전도지연은 3D 거리 기반.
- L(소마-소마 측방거리)은 모델링 값(수상돌기 필드가 겹치는 생물학적 범위 내). 캡션에 명기.

**기하 고정 (2026-08-21, 사용자 지시 "이 기하학적 구조는 fix하자")**
3-2 탐색 결과를 `config/geometry.yaml` 에 **확정값으로 박았다.** 이후 모든 단계는 배치를 다시
탐색하지 않고 `lib/bench.Bench` 로 이 기하를 재현한다.
- pre=oh140807_A0_idF · post=oh140807_A0_idC · θ*=160° · L=120µm
- 시냅스 5개: apic[21]·apic[109]·apic[36]·apic[37]·apic[29], 지연 0.72~0.86ms
- `Bench` 가 두 세포를 로드하고 이 5개 구획을 그대로 찾아 시냅스 '위치'를 제공한다.
  위에 올릴 메커니즘(전도도·수용체·가소성 엔진)은 각 단계가 정한다 — 그게 벤치의 목적.
- geometry.yaml 을 바꾸면 3-2 를 다시 돌려 시냅스 위치·지연을 재생성해야 한다.

## D9 — 시냅스 클래스는 PC->PC 하나다 (SC->PC 삭제)

**결정 (2026-08-21).** 이 벤치의 연결 클래스는 **PC->PC** 하나다. `SC->PC` 는 config 에서 삭제한다.

**왜.** 이 트랙은 "CA1 추체세포 2개를 붙여 시냅스 가소성 모델을 실험하는 페어 벤치"다.
pre·post 가 둘 다 CA1 추체세포이므로 연결의 정직한 이름은 PC->PC 다.

**SC->PC 가 왜 틀렸나.**
- Ecker 2020 Table 3 의 9개 일반화 클래스에 **SC 는 없다** (Table 3 = CA1 내부 연결만).
  `papers/01_.../03_synapses/params_table3.py` 의 `SC->PC (E1s)` 는 그 트랙에서
  "SC 대용 촉진 클래스가 필요하다"며 **만들어 붙인 튜닝값**이고, 파일 주석에도 그렇게 적혀 있다.
- 04 는 독립 트랙이므로 다른 트랙의 튜닝값을 근거 없이 물려받을 이유가 없다.
- 무엇보다 CA3 세포가 없으므로 SC 연결은 이 벤치에 존재하지 않는다.

**어떻게 잘못 들어왔나 (프로세스 실패).** 미결 #7("기본 시냅스 클래스 — 측정된 억압형 vs
튜닝된 촉진형")이 3-1 에서 해결되어야 했는데, 결정 기록 없이 `default_class: SC->PC` 로
조용히 정해졌다. 결정은 반드시 D번호로 남긴다.

**영향.** 3-1 및 그 전제 위에 실행된 3-3·3-4·3-5·3-6 결과물을 삭제하고 PC->PC 로 재실행한다.
3-2(배치)는 기하만 다루므로 클래스와 무관 — 유지(D8 기하 고정 그대로).

**채택값 (Ecker 2020 Table 3 "PC->PC (E2)" 실측, 튜닝 없음).**
g_hat 0.6 nS · tau_d_AMPA 3.0 ms · Use 0.50 · Dep 671 ms · Fac 17 ms · Nrrp 2 · NMDA:AMPA 1.22
-> Fac < Dep 이므로 **억압형**이다. 촉진형이 아니라는 사실을 6단계 해석에서 전제로 둔다.

**촉진 대조가 필요하면** 없는 클래스를 만들지 않고 Table 3 의 실측 촉진 클래스
(PC->SOM+ E1: Use 0.09 / Dep 138 / Fac 670)를 쓴다.

## D10 — 시냅스 표적 구역·개수는 PC->PC 문헌으로 정한다

**결정 (2026-08-21).** 시냅스는 **post 기저수상돌기 + 정단 근위 50~150um** 안에 놓고,
**연결당 2개**만 유지한다. 이전 판(정단 SR 100~300um · 5개)은 폐기한다.

**문헌 근거.**
- **Deuchars & Thomson 1996** Neuroscience 74(4):1009 (PMID 8895869) — 성체 흰쥐 CA1 추체세포
  **989쌍 중 단일시냅스 연결 9개**(약 0.9%, 재귀 연결이 희소함을 실측). 완전 재구성된 1쌍에서
  전시냅스 축삭이 post 의 **3차 기저수상돌기에 접촉 2개**(스파인 1·shaft 1). 4쌍 전부 짝펄스 억압
  -> Ecker Table3 PC->PC(Use 0.50 / Fac 17, 억압형)와 방향 일치.
- **Crepel, Khazipov & Ben-Ari 1997** J Neurophysiol 77:2071 (PMID 9114256) — CA1 국소 재귀
  축삭은 **stratum oriens** 를 지난다(oriens 국소 TTX 로 다시냅스 성분 감소, 역방향 자극으로도
  유발). 전류원밀도상 응답은 **정단 근위 50~150um**(추체층 아래 radiatum)에서 생성.
- **Ecker 2020 Fig.3b** — E->E 연결당 시냅스 수 1.3.

**왜 이전 판이 틀렸나.** 정단 SR 100~300um 은 **Schaffer collateral(CA3->CA1)이 접속하는 층**이다.
D9 로 연결이 PC->PC 로 확정된 이상 SR 배치의 근거가 없다. 개수 5 도 해부 근거가 아니라
"회전각 스윕에서 접촉이 최대가 되는 수"였다.

**재실행 결과 (3-2).** θ* = 330도(표적 구역 접촉 4개) · 유지 2개가 **둘 다 기저수상돌기**
(dend[3] 경로거리 144.3um · dend[23] 171.7um, 접촉거리 7.8/6.2um, 지연 0.76/0.74ms)
-> Deuchars 1996 의 EM 관찰(기저수상돌기 접촉)과 일치한다.

**파생 영향 — 3-5 의 "g 가 10배 크다"는 결론은 무효.**
3-5 는 uEPSP 를 **Sayer 1990(CA3->CA1 = SC)** 과 비교해 "논문 평균의 10.2배"라 판정했다.
이 벤치의 올바른 문헌은 **Deuchars & Thomson 1996(PC->PC)** 이고 그 값은 0.7±0.5 mV(0.17~1.5)다.
게다가 시냅스 수가 5 -> 2 로 줄어 진폭이 약 2.5배 낮아진다(3-3 실측 5개 1.358mV -> 2개 약 0.54mV 추정).
=> 3-7 의 g 재보정 근거가 사실상 사라진다. 재실행 후 실측으로 다시 판단한다.
`lib/refdata.DEUCHARS1996` 에 기준값 등록.

## D11 — NMDA 동역학은 Ecker PC->PC 값(3.9 / 148.5 ms)을 쓴다

**결정 (2026-08-21).** `tau_r_NMDA = 3.9 ms` · `tau_d_NMDA = 148.5 ms`
(Ecker 2020 §2.3, PC->PC, Q10 보정). 이전 값 9.0 / 61.0 은 폐기.

**왜 바꿨나 — 이전 값의 출처 표기가 틀렸다.**
config 에는 9.0/61.0 의 출처가 "Andrasfalvy & Magee 2001 (CA1 특이)" 로 적혀 있었다.
그 논문(PMID 11717348, DOI 10.1523/JNEUROSCI.21-23-09151.2001)을 PubMed 로 확인한 결과:
- 제목이 **"Distance-dependent increase in AMPA receptor number in the dendrites of adult
  hippocampal CA1 pyramidal neurons"** 이다. 주제는 **AMPA 수용체 개수**이고,
  정단 100~250um 에서 AMPA 전류가 약 2배 증가하는 반면 **NMDA 전류 진폭은 변하지 않았다**고
  보고한다. NMDA 시상수를 제시하는 논문이 아니다.
- 게다가 대상 경로가 **Schaffer collateral** 이다 -> 우리 연결(PC->PC)이 아니다.
=> Sayer 1990(3-5 기준 문헌)·SC->PC 클래스와 같은 계열의 **SC 오염**이었다.

**채택 근거.**
- Ecker 2020 §2.3 은 **PC->PC** NMDA 동역학을 명시한다(Q10 보정 후 3.9 / 148.5 ms).
- 우리는 g_hat·tau_d_AMPA·Use·Dep·Fac·Nrrp·NMDA:AMPA(1.22) 를 모두 Ecker Table3/§2.3 에서
  가져왔다. NMDA:AMPA 비는 그 NMDA 동역학과 함께 산출된 값이므로, 감쇠만 다른 출처로 바꿔 끼우면
  내부 불일치가 생긴다. **같은 연결·같은 출처**로 통일하는 것이 D9 의 원칙과 일치한다.
- 온도 정합: `lib/nrnenv.CELSIUS = 34.0`, Ecker 시뮬 온도도 34도 -> 보정값 직접 사용 가능.

**파생 영향 (반드시 반영).**
NMDA 감쇠가 61 -> 148.5 ms 로 약 2.4배 길어져 **NMDA 전하량(따라서 시냅스 칼슘 총량)이 크게 는다.**
- 3-3~3-6 은 이 값으로 재실행한다(EPSP 후반부 꼬리가 길어져 반치폭·감쇠가 커질 것).
- 5단계 칼슘 기반 가소성(GB 계열·GluSynapse)의 문턱·이중안정 파라미터는 **이 NMDA 위에서** 잡아야
  한다. GB mod 기본값이 짧은 NMDA 를 전제로 적합된 것이면 그 사실을 5-1 에 명기한다.

## D12 — 자극은 정착(250ms) 이후에 준다 · EPSP 측정은 lib.measure 로 통일

**결정 (2026-08-22).** 모든 단계에서 자극은 `lib.wiring.SETTLE_MS = 250 ms` 이후에 주고,
EPSP 진폭은 예외 없이 `lib.measure.epsp_features`(기저선 = 자극 직전 5 ms 평균)로 잰다.
다시행 실험은 `Wiring.settle()` 로 한 번 정착한 뒤 `restore()` 로 스냅샷 복원해 반복한다.

**왜 — 같은 EPSP 를 세 단계가 다르게 재고 있었다.**
PC->PC 재실행에서 같은 자극·같은 기하인데 3-3 = 0.621 · 3-4 = 0.705 · 3-5 = 0.493 mV 가 나왔다.
40 % 차이라 원인을 실측했다(자극 없이 1000 ms 진행, post 소마):

| t (ms) | post Vm (mV) | 정상상태(-69.5519) 대비 |
|---|---|---|
| 5 | -69.6802 | -0.128 |
| 10 | -69.4407 | +0.111 |
| **20** | **-69.3244** | **+0.228** |
| 50 | -69.4724 | +0.080 |
| 100 | -69.5435 | +0.008 |
| 200 | -69.5508 | +0.001 |
| 500 | -69.5518 | 0.000 |

`v_init = -70` 에서 시작하면 세포가 자기 정지전위로 가며 **오버슈트 후 서서히 정착**한다.
자극 시각이 t = 20 ms 였으므로 기저선이 표류 중이었고, 기저선 창을 어떻게 잡느냐가 그대로
진폭 오차가 됐다 — t = 20 에서 '직전 5 ms 평균' 과 '0~20 ms 전체 평균' 의 차이가 **0.2153 mV**.
실제 관측된 3-4(0.705) - 3-5(0.493) = **0.212 mV** 로 정확히 일치한다. 원인 확정.

**영향.** EPSP 가 0.5 mV 수준이므로 이 표류는 **30~40 % 오차**다. 5·6 단계 가소성은 EPSP
진폭비로 효능을 재므로, 고치지 않으면 모든 가소성 수치에 계통오차가 실린다.

**조치.**
- `lib.wiring.SETTLE_MS = 250.0` (실측 근거: t >= 200 ms 에서 잔류 표류 0.001 mV).
- `Wiring.settle()` / `restore()` / `run_settled()` 추가 — NEURON `SaveState` 로 정착 상태를
  스냅샷. 3-6(200 시행)은 정착을 1회만 하므로 **더 빨라진다**(시행당 40 ms 만 진행).
- 3-3 의 자체 진폭 계산(`v.max() - v[t<delay].mean()`)을 `measure.peak_amp` 로 교체.
- 3-3·3-4·3-5·3-6 모두 `T_SPIKE = SETTLE_MS + 10` 으로 재실행.

**교훈.** 세 단계가 같은 양을 다르게 재고 있었다는 사실 자체가 버그 신호였다.
동일 물리량은 한 함수로만 잰다 — 단계마다 인라인으로 계산하면 이런 불일치가 조용히 남는다.

## D13 — g 는 논문값 0.6 nS 로 확정(튜닝 안 함) + 국소 스파이크 문턱 발견

**결정 (2026-08-23).** `g_nS = 0.6` (Ecker 2020 Table 3 PC->PC(E2) 논문값)을 **그대로 확정**한다.
3-7 은 '재보정' 단계가 아니라 '확정 + 민감도 문서화' 단계다.

**왜 튜닝하지 않는가.** g=0.6 nS 에서 uEPSP = **0.524 mV** 로, Deuchars & Thomson 1996 실측
범위(0.17~1.5 mV) **안**이고 평균(0.7 mV)의 0.75 배다. 평균에 정확히 맞추려면 g≈0.82 nS 가
필요하지만(스윕 보간), 그렇게 하면 **논문값이 튜닝값으로 바뀐다.** D9 의 '튜닝값 0개' 를 깨는
대가가 '평균에 0.18 mV 더 가까움' 보다 크다. 평균 정합 g 는 JSON·그림에 기록만 한다.

**g 스윕 결과 (시냅스당 g, 시냅스 2개).**

| g (nS) | soma uEPSP (mV) | 상승 (ms) | 국소 최고 전압 (mV) | 구분 |
|---|---|---|---|---|
| 0.10 | 0.098 | 2.25 | -66.0 | 수동 |
| 0.30 | 0.278 | 2.27 | -61.7 | 수동 |
| **0.60** | **0.524** | **2.35** | **-56.1** | **수동 · 채택** |
| 0.80 | 0.683 | 2.40 | -52.7 | 수동 |
| 1.00 | 0.892 | 2.57 | -48.4 | 수동 (천장) |
| 1.10 | 3.761 | 1.25 | **-1.7** | 국소 스파이크 |
| 1.20 | 4.864 | 0.85 | **+11.9** | 국소 스파이크 |
| 2.00 | 4.737 | 0.75 | +10.5 | 국소 스파이크 |

수동 구간 기울기 0.882 mV/nS · 원점통과 선형 대비 최대 편차 10.6 %(포화 — NMDA 전압의존·구동력 감소).

**★ 새로 발견한 제약 — 국소(수상돌기) 스파이크 문턱.**
g >= 1.1 nS 에서 기저수상돌기 국소 전압이 -48 mV -> -2 mV -> +12 mV 로 뛰고 상승시간이
2.4 ms -> 0.8 ms 로 빨라진다. **수동 EPSP 가 아니라 국소 스파이크**다(소마 스파이크는 아니다 —
소마에는 4.7~4.9 mV 로 감쇠돼 도달). 따라서:
- **수동 uEPSP 천장은 약 0.89 mV** 이고, **Deuchars 실측 상한 1.5 mV 는 이 기하에서 수동으로
  도달 불가**(천장이 상한의 0.59 배). 논문의 큰 uEPSP 는 시냅스 수·위치가 다른 연결일 것이다.
- **채택 g 대비 스파이크 여유는 1.83 배.** 즉 5·6 단계에서 가소성이 효능을 1.8 배 이상 올리면
  연결이 **정성적으로 다른 영역**(국소 스파이크)으로 넘어간다. LTP 실험에서 효능비만 보고
  '더 큰 EPSP' 로 해석하면 오독이다 — 6-x 에서는 상승시간·국소 전압을 함께 기록해
  스파이크 여부를 판정해야 한다. (docs/EXPERIMENTS.md 6단계 주의사항에 반영)

**부수 확인.** 이 스윕은 정착 스냅샷(D12)을 1회만 만들고 g 만 바꿔 13회 실행했다 —
gmax 는 파라미터이므로 정착 상태와 무관하다. 정착을 매번 하는 것보다 훨씬 빠르다.
